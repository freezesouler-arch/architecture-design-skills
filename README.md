# Architecture Design Skills

**建筑设计中的 AI 工作方法：白模表达 · 方案推导 · 片区策划。**

[English](README.en.md) · [使用示例](examples/README.md) · [MIT License](LICENSE)

把设计实践中的质量要求写成可复用的 Agent Skills：保持原模型与表达一致，用可追溯证据支持设计决策，把城市目标落实为空间、指标和实施责任。

## 三个技能，按任务选择

| 技能 | 适合什么时候用 | 主要输出 |
|---|---|---|
| [建筑精细白模](skills/architectural-white-model/SKILL.md) | 已有模型截图，希望统一白模表现并保持原方案 | 图像编辑提示词、几何锚点、逐图检查与修复记录；有图像编辑工具时生成成品 |
| [建筑设计工作流](skills/architectural-design-workflow/SKILL.md) | 从模糊需求到概念备选、模型校核和设计汇报 | 项目简报、案例矩阵、设计驱动、方案对比、问题单与交付结构 |
| [片区概念策划](skills/district-concept-planning/SKILL.md) | 产业园、片区更新、功能调整与政府/开发商汇报 | 基线与反事实、公共价值清单、指标责任表、概念方案与叙事 |

三个技能可单独使用，不必每次启动全部流程。它们是工作方法与检查规则，不是独立建模软件或一键审批系统。

## 安装

下载本仓库 ZIP，或运行：

```sh
git clone https://github.com/freezesouler-arch/architecture-design-skills.git
```

将 `skills/` 中需要的**整个技能文件夹**复制到你的 Agent 技能目录，保留内部 `references/` 和 `agents/`。不要只复制 SKILL.md。

- Codex：使用你当前配置的 skills 目录；通常是 `$CODEX_HOME/skills`，未自定义时是 `~/.codex/skills`。
- 其他支持 SKILL.md 的 Agent：按该工具的技能加载方式安装；本仓库未逐一验证兼容性。
- 不支持自动加载技能时：让助手读取目标 SKILL.md，并按需读取其引用文档。

重新加载技能后，按名称调用。已安装同名技能时先备份再替换；公开版本不包含私人项目偏好。

## 直接复制这些请求

### 1. 把模型截图转成白模

> 使用 $architectural-white-model，把我上传的模型截图转为精细白模。保持楼栋数量、屋顶、相机、岸线和水域边界；只改变材质与光照。先记录几何锚点，生成后逐项核对并报告实际像素。

需要上传自己的底图，并提供能接收参考图的图像编辑工具。工具缺失时仅能输出提示词与检查清单；技能本身不附带 API、额度或模型服务。

### 2. 从需求进入概念设计

> 使用 $architectural-design-workflow，为一个社区文化中心整理简报和设计驱动。先区分事实、假设和待核实项，再研究可比案例，提出有实质差异的概念备选。当前只做概念前期，不制作施工图。

### 3. 梳理片区更新逻辑

> 使用 $district-concept-planning，梳理一个产业园更新项目。比较维持现状与功能复合的情景，说明产业底盘、人才生活缺口、公共价值和实施责任，形成开发商决策汇报提纲。没有依据的数字留空。

## 核心原则

- **底图有身份**：每个视角对应自己的几何依据，风格参考不提供布局事实。
- **方案有证据**：标杆研究提炼机制，不能只收集好看的图片或复制形态。
- **数字有口径**：记录单位、范围、来源与日期，区分事实、建议和愿景。
- **承诺有责任**：公共空间、设施与运营目标对应实施主体、节点和核验方式。
- **修改有边界**：保留已确认部分，定点修复并回查受影响视图。

## 环境与限制

阅读与组织文本只需支持文件读取的 AI 助手。实时案例/政策核查需要检索能力；模型分析需要用户自备模型及合适软件；白模生成需要用户授权的图像编辑能力。未绑定 GrsAI 或任何专有服务。

本仓库不附带客户资料、私人图库、项目模型、API Key 或实际项目成品。示例为说明用途的虚构任务与验收要点，不是已完成项目或生成效果承诺。法规、结构、消防和工程计算需由相应专业人员复核；图像生成无法保证尺寸或几何完全准确。
