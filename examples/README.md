# 使用示例与验收要点

以下均为虚构教学情景，不含实际项目数据。示例描述应该检查什么，不冒充模型已执行的结果。

## 白模：滨水社区鸟瞰

输入：使用者自己的鸟瞰截图，含三栋建筑、一条河、一个环形亭；另有一张可授权的风格参考图。

请求：使用 $architectural-white-model，仅统一白模材质与自然光，不改变主体。

执行要点：

1. 将截图指定为几何依据，另一张图指定为风格参考。
2. 登记三栋建筑的位置与高低关系、环亭开口、河道两岸、原相机与画幅。
3. 用实际可用的图像工具编辑，记录工具、输入版本与输出尺寸。
4. 对照底图复核；若背景陆地被改成水，只修复错误水域，锁定主体。

验收记录样式：

| 项目 | 判定方式 |
|---|---|
| 楼栋与屋顶 | 与底图逐栋对应，遮挡部分列为不可确认 |
| 陆水边界 | 两岸连续，青色铺装不误判为水 |
| 环形亭 | 保留中庭开口，不生成实心圆盘 |
| 输出规格 | 从文件读取实际宽高，不按提示词推定 |

没有图像工具时应交付提示词和检查清单，说明图片未生成。

## 建筑设计：社区文化中心

输入：虚构需求为“提供阅读、工作坊和共享活动空间”；尚无场地、面积、预算和法规资料。

请求：使用 $architectural-design-workflow，先做简报与方向研究，不把未知数字补成事实。

预期工作结构：

- 已知：功能目标与使用人群；待确认：场地、规模、运营主体与预算。
- 暂定方向：围绕日常开放、活动弹性和安静/活跃区分布提出不同空间机制。
- 案例矩阵：来源、机制、适用条件、可转译动作与不可复制形态。
- 备选比较：比较真实功能与动线差异，不仅比较外观风格。
- 下一步：在场地和运营条件明确后复核，不声称已达到当地领先水平。

通过标准：每个确定性结论可追溯；未取得资料的条件留作假设；不输出虚构审批结论。

## 片区策划：研发园更新

输入：虚构场景为“已有研发楼宇，管理方希望研究是否增加生活服务”；当前缺少供需统计。

请求：使用 $district-concept-planning，形成开发商内部决策提纲，比较维持现状、增加服务与分期试点。

预期链条：

`供需事实待补 → 三种情景 → 可验证的公共价值 → 空间动作 → 责任与核验`

| 待研究问题 | 所需证据 | 可讨论动作 |
|---|---|---|
| 服务是否真的不足 | 服务人口、营业时段、步行覆盖和现有容量 | 复合首层或共享服务设施 |
| 公共空间是否可达 | 路径、开放边界、入口及开放时间 | 连续慢行网络与运营规则 |
| 运营能否兑现 | 资金、主体、维护与需求证据 | 分期试点、年度复评与退出机制 |

通过标准：不把“增加咖啡馆”直接当成指标承诺，不以案例密度冒充法定标准；每项建议对应边界、主体、节点与验证材料。
