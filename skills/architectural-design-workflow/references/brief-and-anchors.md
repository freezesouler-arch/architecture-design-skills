# 项目简报与锚点

## 最小项目简报

先复用用户已有资料。缺失项可以用假设继续，但必须标注置信度和验证方式。

| 类别 | 需要捕获的内容 |
|---|---|
| 项目身份 | 项目名、类型、地点、阶段、委托方、开发商品牌/产品线、主要使用者 |
| 市场定位 | 目标客群、价格带、竞品、销售目标、品牌承诺、市场层级与成功样本 |
| 目标 | 设计命题、体验目标、商业/公共价值、成功指标 |
| 场地 | 边界、地形、朝向、气候、交通、景观、周边、权属与现状 |
| 规模 | 用地、容积率/密度、建筑面积、层数、高度、房间或单元数量 |
| 约束 | 法规、退界、消防、无障碍、预算、工期、施工条件、保护要求 |
| 性能 | 日照、采光、能耗、声学、通风、碳、水、韧性目标 |
| 表达 | 风格倾向、禁用方向、参考案例、材料、图像比例与视角 |
| 交付 | 模型格式、图纸深度、图像数量、文本类型、截止时间、评审对象 |

对关键数值记录“数值 + 单位 + 来源 + 日期 + 适用阶段”。当地法规和现场资料不能仅凭记忆填写。

## 锚点登记表

锚点不是越多越好，只记录跨阶段必须保持或有意变更的项目 DNA。

### 身份锚点

项目类型、规模、层数、核心用户、空间性格和不可接受方向。

### 几何锚点

场地边界、坐标与北向、体量关系、层高、核心筒/庭院位置、屋顶类型、主要出入口、开窗节奏和固定相机。

### 材料锚点

主材、辅材、玻璃/金属色调、表面粗糙度、可替代范围和禁止替换项。

### 性能锚点

面积上下限、关键净宽/净高、疏散与无障碍底线、日照/采光目标、造价或碳目标。

### 表达锚点

图像时间、季节、天气、人物密度、镜头语言、图纸配色和文字口吻。表达锚点不得覆盖几何与性能事实。

每条锚点包含：`id`、`value`、`status`（proposed/approved/frozen）、`source`、`version`、`change_reason`。

## 概念备选

每个备选至少回答：

- 核心命题是什么；
- 回应了哪条市场洞察、转译了什么机制、拒绝复制什么；
- 场地与人流如何组织；
- 体量和关键空间如何形成；
- 结构、环境与经济逻辑是否初步成立；
- 最大优势、最大风险和最快验证动作是什么。

避免只改变外观风格的“伪备选”。比较矩阵应使用与项目目标对应的 5–8 个指标，权重必须显式，评分旁边保留证据与不确定性。
