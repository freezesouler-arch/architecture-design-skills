# 模型、图像与质量校核

## 单一几何真源

确定一个权威模型，其他图纸与图像均能追溯到其版本。模型至少包含：

- 场地坐标、北向、基准点和单位；
- 楼层、轴网、主要标高和体量；
- 空间/房间及面积属性；
- 墙、板、屋顶、柱、核心、门窗和主要交通；
- 材料 ID 与对象分类；
- 固定相机、剖切面和导出视图；
- 来源、作者/生成方式、版本和更新时间。

概念模型可以简化构造，但不能伪装成更高 LOD。交换时优先使用开放格式（如 IFC、glTF/GLB、OBJ、DXF、CSV/JSON 属性表），并记录丢失的信息。

## 推荐文件语义

使用稳定的对象 ID，不依赖显示名称做关联。建议命名：

`{project}-{discipline}-{level/zone}-{object/view}-{version}`

版本升级发生在锚点、几何或关键数据改变时；仅渲染参数变化可使用同一模型版本下的表达版本。

## 固定视角与图像一致性

在定案表现前，从权威模型导出每个视角的灰模或线稿，并保存：相机位置、目标点、焦距/视场角、画幅、裁切和时间/太阳参数。

给图像生成或编辑系统的输入应包含：

- 项目身份与当前版本；
- 对应灰模/线稿；
- 该视图能看见的几何、材料和表达锚点；
- 允许修改项；
- 必须保持项；
- 禁止增加项；
- 期望输出尺寸与用途。

审查图像时检查轮廓、层数、屋顶、开口、庭院、入口、材料、尺度参照、景观边界和相邻视图的接缝。不要把带人物、植物或家具的视觉遮挡当作几何证明。

## 综合校核矩阵

按项目阶段选择适用项：

| 维度 | 典型检查 | 证据 |
|---|---|---|
| 简报 | 面积、房间数、用户需求、交付深度 | Brief、面积表、需求追踪矩阵 |
| 场地/法规 | 退界、高度、密度、日照、停车、保护 | 来源链接、法规摘录、总图、计算 |
| 功能/体验 | 邻接、流线、可达、视线、公共/后勤分离 | 泡泡图、平面、路径分析 |
| 安全/无障碍 | 疏散距离、出口、净宽、坡道、电梯、消防假设 | 标注平面、核算表、问题单 |
| 几何 | 平剖立对应、标高、层数、屋顶、开口、碰撞 | 模型视图、剖切、自动检查 |
| 结构/机电 | 跨度、网格、竖向连续、设备空间、管井 | 专业假设图、碰撞记录 |
| 环境 | 朝向、遮阳、采光、通风、能耗、水与碳 | 分析模型、输入参数、结果图 |
| 经济/建造 | 面积效率、材料、模数、工序、造价风险 | 指标表、工程量/估算、构造草图 |
| 表达 | 跨视图一致、图文一致、来源与假设标注 | 固定视图对照、Artifact Index |

法规、结构、消防和工程计算必须由有资质人员按适用阶段复核；工作流输出只能作为设计辅助与问题发现。

## 问题单与定点修复

每个问题包含：`issue_id`、对象/视图、发现版本、严重度、描述、证据、预期结果、允许修改、必须保持、负责人、状态、验证方法。

修复后不要只看目标画面：回归检查所有共享该锚点或几何对象的图纸、视图、面积表和文本。无法自动证明时，保留人工复核项。

建议严重度：

- `S0`：安全、法规或数据完整性风险，阻止交付。
- `S1`：关键几何/功能错误，阻止阶段冻结。
- `S2`：明显一致性或表达问题，应在正式汇报前修复。
- `S3`：优化建议，可进入后续迭代。
