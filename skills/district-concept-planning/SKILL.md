# 片区概念方案

把片区概念方案视为一份“城市价值与实施责任的决策提案”，而不是设计图册。先证明为什么值得做、为什么需要改变以及改变后城市得到什么，再讨论空间如何实现。

## 开始前

先识别本轮对象和决策：开发商内部决策、政府前置沟通、规划调整论证、方案评审或综合汇报。复用用户已有文本、强排、指标和案例，不要求重复提供。

建立四类信息并保持区分：

- `已确认事实`：权属、用地性质、规模、容量、现状供给、政策条文及来源日期；
- `分析判断`：供需关系、结构性短板、机会与风险；
- `项目建议`：功能、指标、实施与运营承诺；
- `愿景表达`：城市定位和长期影响，不写成已实现事实。

涉及现行政策、规划标准、市场数据或国际项目数据时，核实最新的一手来源。不得把案例宣传语、效果图或单位面积经验值冒充法定标准。

## 核心决策链

按当前任务裁剪，但不得跳过必要性和公共价值：

1. **基线与反事实**：若维持现状，产业、居住、公共服务和开发实施会怎样；现有条件已经解决什么、仍缺什么。
2. **城市级命题**：把地块问题上升为全球城市竞争、人才留存、产业韧性、公共生活或生态治理问题，避免从户型和造型起笔。
3. **调整必要性**：说明拟调整内容、未调整的核心底盘、不可替代的结构性缺口，以及“不调整 / 调整”两种情景的城市结果。
4. **案例因果证据**：研究政策、治理、产业、空间和运营如何共同产生结果，不把案例缩减为设计手法图库。
5. **价值主张**：形成3–5个能同时回应城市、产业、人才和开发实施的目标；目标必须能向指标与空间落实。
6. **公共价值交换**：明确项目获得的规划或功能弹性，与城市获得的公共空间、服务、产业平台、住房、交通、生态和运营责任。
7. **概念转译**：从目标推导功能体系、公共空间骨架、交通、生态、体量与场景；设计原则高于具体造型手段。
8. **兑现机制**：用规划条件、开发协议、分期节点、验收口径、运营KPI和年度评估保证长期落地。

详细执行流程读取 [references/workflow.md](references/workflow.md)。

## 案例使用规则

概念或战略重构前必须做案例检查门。每个核心案例按以下链条拆解：

`起点问题 → 锚点机构/主体 → 政策与规划工具 → 空间及运营机制 → 可验证结果 → 成立条件 → 对本项目的转译`

至少包含市场基线、同类标杆和相邻创新三类案例。优先选择城市政府、规划机构、开发运营方、大学或企业官方资料。明确哪些是事实、哪些是本项目推断；禁止只因形象相似而引用案例。

需要建立对标框架或案例页时，读取 [references/benchmarking-and-causality.md](references/benchmarking-and-causality.md)。

## 叙事规则

- 每页只承担一个判断，标题直接说结论；正文解释因果，图表提供证据。
- 开发商内部汇报可以呈现资产效率、销售与退出条件，但必须同步说明政府为何会接受、公共责任如何兑现。
- 政府沟通不掩饰调整诉求，也不以命令口吻“教政府做事”；使用“项目可承担”“建议共同研究”“可纳入条件约束”等协商表达。
- 先讲城市和结构性问题，再讲设计；效果图只用于证明空间结果，不能代替政策、供需和实施论证。
- 同一概念必须在目标、案例、指标、方案和总结页保持同名同义，避免章节间换词漂移。
- 目标页与总结页统一；案例启示必须在后文找到对应的指标、空间或运营动作。

针对不同汇报对象和篇幅，读取 [references/narrative-architectures.md](references/narrative-architectures.md)。

## 指标与承诺

不要直接复制“每平方公里多少咖啡馆”等数字。先说明统计边界、服务人口、现状、可比口径和来源，再计算项目责任：

`片区目标需求 − 现状有效供给 − 已落实供给 = 片区缺口`

`项目建议 = 片区缺口 × 项目合理承担比例`，并结合建筑容量、运营可行性和分期复核。

指标至少区分：

- 容量指标：面积、数量、比例；
- 可达指标：5/10/15分钟覆盖、步行与公共交通连接；
- 品质指标：开放时段、界面连续性、环境性能；
- 运营指标：活动、企业服务、孵化、客流、使用率；
- 治理指标：责任主体、交付节点、验收方式和复评频率。

需要编制指标表、公共价值清单或政府问答时，读取 [references/metrics-governance-and-qa.md](references/metrics-governance-and-qa.md)。

## 设计转译检查

每条城市目标均建立闭环：

`城市问题 → 目标 → 设计原则 → 空间/功能动作 → 指标 → 实施主体 → 验证材料`

设计原则应能指导多种方案，例如“公共优先”“生态连续”“开放复合”；避免把“做一条空中连廊”“设置一个广场”等单一动作写成最高层导则。具体动作放在解释或工具箱中。

## 交付前检查门

- 是否先回答“城市为什么需要”，而不是只回答“方案长什么样”；
- 是否用反事实证明调整必要性，并说明保留不变的产业或公共底盘；
- 案例是否有因果关系、适用条件和可转译机制；
- 所有关键数字是否有单位、范围、来源、日期和计算关系；
- 项目获得的权益与城市获得的价值是否一一对应；
- 目标是否落实到指标、空间、分期、运营和责任主体；
- 汇报语气是否符合对象，愿景是否与事实分开；
- 是否存在重复页面、文不对题、目标名称漂移或设计表达抢占战略结论。

若检查门未通过，先输出差距清单、建议删并页和最小补证动作；不要用更多案例或更精美图片掩盖逻辑缺口。
